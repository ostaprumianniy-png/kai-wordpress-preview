# KAI visual correction reference

Goal: keep the existing information architecture, WordPress theme/plugin and bilingual behavior, but raise the visual product quality toward the screenshots in this folder.

- Use the real supplied KAI logo/wordmark prominently; the current generic K-mark is not the target.
- Keep a dark graphite base, off-white type and cyan as the main UI accent. Blue/violet may appear only as restrained brand glow inherited from the KAI logo.
- Make the hero feel like a product, not documentation: stronger branded visual, device mockups/screens, tighter hierarchy, less empty dark space.
- Keep technical credibility (version, status, checksum) but move micro-metadata below the user decision; do not let tiny monospace text dominate.
- Download cards should feel like real software product cards: platform, short benefit, version/status, one obvious primary action and a visual preview.
- Use generous spacing but not sparse emptiness. Sections should have distinct visual anchors and stronger rhythm.
- Preserve accessibility, responsive behavior, EN/UK language support, honest demo/production states and all existing backend adapter logic.
- Do not copy the reference literally. Treat it as the target mood, hierarchy and product polish while retaining the working WordPress implementation.
